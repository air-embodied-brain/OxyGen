# LIBERO visual-memory language adapter

This experiment adds a private autoregressive language suffix to the released
pi0.5 LIBERO policy. The suffix describes task progress already visible in the
current observation:

```text
Memory: The alphabet soup is in the basket.
```

The observation, robot state, and task instruction are encoded once by the
frozen base model. The action expert reads this unchanged root KV cache.
Language generation creates its own fixed-size append state and enables a
rank-16 LoRA only for the seed and generated suffix tokens. Generated memory is
not fed back to the action expert.

## Contents

- `build_split.py`, `data.py`: deterministic train/validation split and HDF5
  loading.
- `train.py`: full-sequence LoRA, suffix-only LoRA, and final-MLP comparison;
  the selected model uses the deployed incremental suffix path.
- `evaluate.py`, `scan_checkpoints.py`: held-out generation, action/root-cache
  invariance, latency, and checkpoint selection.
- `serve_adapter.py`, `verify_serving.py`: OxyGen continuous batching and a
  blocking openpi baseline with separate action/language prefix forwards.
- `rollout_review.py`: deterministic LIBERO rollout capture and review pages.
- `build_demo_review.py`, `range_http_server.py`: publication-style demo
  rendering and local HTTP Range serving.
- `prepare_hf_release.py`: portable model/dataset staging with host-local paths
  removed from the dataset manifest.
- `benchmark_throughput.py`: controlled fixed-length throughput benchmark.

Predicate extraction and text-rule generation live in
`experiments/libero_language_supervision`.

## Prerequisites

Prepare the following assets outside Git:

1. the official raw LIBERO HDF5 demonstrations;
2. the released pi0.5 LIBERO checkpoint and its `norm_stats.json`;
3. predicate annotations generated by the supervision pipeline.

The selected adapter checkpoint is also stored outside Git. Its release
manifest is listed in [RESULTS.md](RESULTS.md).

## Build the split

The final experiment uses all four standard suites, holds out five episodes
per task, samples every eighth frame, and adds frames around memory changes.

```bash
python -m experiments.libero_language_adapter.build_split \
  --annotation-root /path/to/libero_all_v6 \
  --dataset-root /path/to/raw_libero \
  --language-target visual_memory \
  --output /path/to/visual_memory_split.json
```

## Train

The selected run uses rank-16 suffix LoRA on the Q/K/V/O and gated/up/down FFN
projections in all 18 language layers. Training and validation follow the same
incremental seed-plus-token path used by serving.

```bash
CUDA_VISIBLE_DEVICES=0 XLA_PYTHON_CLIENT_MEM_FRACTION=0.99 \
python -m experiments.libero_language_adapter.train \
  --split /path/to/visual_memory_split.json \
  --checkpoint /path/to/pi05_libero \
  --norm-stats /path/to/pi05_libero/assets/physical-intelligence/libero/norm_stats.json \
  --adapter-type suffix_lora --rank 16 --alpha 16 \
  --suffix-seed 'Memory: ' --suffix-len 28 \
  --loss-mode incremental \
  --sampling-mode task_target_balanced \
  --validation-sampling-mode task_target_balanced \
  --validation-samples-per-task 10 \
  --learning-rate 1e-4 --steps 1500 --warmup-steps 100 \
  --eval-every 250 --output-dir /path/to/visual_memory_run
```

The final selection compared learning rates `1e-4`, `3e-5`, and `1e-5` on the
same 400-sample task/state-balanced incremental greedy set.

## Evaluate

```bash
CUDA_VISIBLE_DEVICES=0 XLA_PYTHON_CLIENT_ALLOCATOR=platform \
python -m experiments.libero_language_adapter.evaluate \
  --split /path/to/visual_memory_split.json \
  --checkpoint /path/to/pi05_libero \
  --norm-stats /path/to/pi05_libero/assets/physical-intelligence/libero/norm_stats.json \
  --adapter /path/to/adapter_step_1500.npz \
  --adapter-type suffix_lora --rank 16 --alpha 16 \
  --suffix-seed 'Memory: ' --suffix-len 28 \
  --teacher-forced-samples 5082 --teacher-forced-loss-mode incremental \
  --samples-per-task 10 --action-invariance-samples 20 \
  --output-dir /path/to/evaluation
```

This reports full held-out token accuracy, task/state-balanced greedy
generation, fixed-noise action invariance, root-cache invariance, and the
adapter's incremental latency relative to a shared prefix forward.

## Serve and roll out

Start OxyGen with one new memory request per action replan:

```bash
CUDA_VISIBLE_DEVICES=0 python -m experiments.libero_language_adapter.serve_adapter \
  --checkpoint /path/to/pi05_libero \
  --norm-stats /path/to/pi05_libero/assets/physical-intelligence/libero/norm_stats.json \
  --adapter /path/to/adapter_step_1500.npz --rank 16 \
  --language-seed 'Memory: ' --max-decoding-steps 28 \
  --request-mode new_each_call --steps-per-frame 1 \
  --execution oxygen --port 8011
```

Run the same action policy with blocking language generation by changing only:

```text
--execution blocking_baseline
```

The blocking baseline computes independent action and language prefixes, then
finishes language generation to EOS or the token limit before returning the
action chunk. It does not use a per-frame token budget.

Capture a rollout:

```bash
python -m experiments.libero_language_adapter.rollout_review \
  --host 127.0.0.1 --port 8011 \
  --suites libero_10 --task-id 6 --episodes 0,1,2,3,4 \
  --replan-steps 5 --seed 7 \
  --wall-clock-timeline --raw-timeline \
  --video-fps 100 --source-control-hz 20 \
  --output-root /path/to/review
```

With `new_each_call`, every action replan creates a memory request from the
same current observation. OxyGen advances the new request and all unfinished
requests together while generating actions only for the newest observation.
At LIBERO's 20 Hz control rate and `replan_steps=5`, requests arrive at 4 Hz.

## Render the comparison demo

`build_demo_review.py` consumes saved OxyGen and blocking-baseline rollouts and
renders measured server-inference time followed by 1x simulator time. Client
transport and serialization are intentionally excluded from this visualization
until the response schema is changed to return deltas rather than every active
request's full token history.

```bash
python -m experiments.libero_language_adapter.build_demo_review \
  --oxygen-root /path/to/oxygen_rollouts \
  --baseline-root /path/to/blocking_rollouts \
  --output-root /path/to/demo_review

python -m experiments.libero_language_adapter.range_http_server \
  --directory /path/to/demo_review --bind 127.0.0.1 --port 8767
```

Use `--layout vertical --task-id 6` for the 3:4 mobile version.

## Stage release assets

The release helper creates separate Hugging Face model and dataset directories.
It includes the selected adapter, compact metrics, model/dataset cards, the
2,000 derived JSONL trajectories, and portable QA metadata. It deliberately
omits raw LIBERO HDF5 demonstrations and per-run intermediate files.

```bash
python -m experiments.libero_language_adapter.prepare_hf_release \
  --adapter /path/to/adapter_step_1500.npz \
  --annotation-root /path/to/libero_all_v6 \
  --summary experiments/libero_language_adapter/results/2026-08-13/visual_memory_v1/summary.json \
  --output-root /path/to/hf_release
```

Use `--hardlink` for local staging on the same filesystem. Upload the generated
`model/` and `dataset/` directories as separate repositories after reviewing
their cards and namespace.

## Release status

The data, training, evaluation, serving, blocking-baseline, and demo paths are
implemented and covered by targeted tests. Two release tasks remain:

1. Change continuous-batching responses to send token/status deltas instead of
   every active request's full token history, then restore client-observed
   timing in the demo. The current demo uses measured server inference time so
   this transport artifact does not affect its reported comparison.
2. Upload the staged model and dataset directories to reviewed Hugging Face
   namespaces and replace the local asset manifest with public links.

No additional training is required. The first item and a short serving smoke
benchmark should be completed before merging this feature into `main`.
